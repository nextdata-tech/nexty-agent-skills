# B11: CRM pipeline drift

This full-tier package starts with B1's 22 operator turns and event cards. The
first supervisor-attributed publication freezes the v1 release, switches the
mock `/deals` route to v2, retires the prefix stage decision, and opens an
18-slot refresh suffix. The source switch is hidden from the agent. The
separate workflow must be approved, reviewed, published, and queried.

The five original stage values remain official. The delivered final business
ruling permits provisional `verbal_commit` rows in the four-field result with
an executable, non-blocking warning for out-of-list stages. The follow-up
checks a captured verifier's reachable WARNING branch, its compiled source
hash, a verified publication, and the independent v2 query rows. That is
structural verifier-present-and-ran evidence plus observed publication; the
supervisor does not provide a per-promise WARNING outcome.

The grader reads runner-owned `chain-state.json`, `source-turns.json`, the
operator observations, seven supervisor history artifacts and their linked
captures. Missing or ambiguous runner history is incomplete evidence. A
finished agent attempt without a valid prefix or required refresh is a
failure. The scenario declares two synthetic email markers; raw source JSON
and independent gold remain in the harness-only oracle area.
